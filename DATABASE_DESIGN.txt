STEM LAB PLATFORM - DATABASE DESIGN
=====================================

This document describes the database structure for the STEM Lab platform.
You can use this to recreate the database diagram in draw.io or any ER diagram tool.

COLOR CODING:
- Blue: Core entity tables
- Yellow: Junction/relationship tables
- Red: Transaction/activity tables

================================================================================
CORE ENTITY TABLES
================================================================================

1. users
   - id (PK)
   - name
   - email (UNIQUE)
   - role (admin, teacher, student)
   - is_active
   - email_verified_at
   - password
   - remember_token
   - created_at, updated_at

2. subjects
   - id (PK)
   - subject_name
   - description
   - icon_url
   - image_url
   - display_order
   - is_active
   - created_at, updated_at

3. school_classes
   - id (PK)
   - name (UNIQUE)
   - description
   - is_active
   - created_at, updated_at

4. schools
   - id (PK)
   - name (UNIQUE)
   - address
   - phone
   - email
   - district
   - region
   - is_active
   - created_at, updated_at

5. clubs
   - id (PK)
   - name (UNIQUE)
   - description
   - image_path
   - is_active
   - created_at, updated_at

6. model3ds
   - id (PK)
   - subject_id (FK → subjects)
   - name
   - file (GLB file path)
   - thumbnail
   - description
   - tags
   - is_active
   - created_at, updated_at

7. vr_experiments
   - id (PK)
   - name
   - description
   - external_url
   - thumbnail
   - school_class_id (FK → school_classes)
   - subject_id (FK → subjects, nullable)
   - is_active
   - created_at, updated_at

8. competitions
   - id (PK)
   - name
   - slug (UNIQUE)
   - description
   - terms_and_conditions
   - instructions
   - cover_image
   - club_id (FK → clubs)
   - min_members, max_members
   - min_age, max_age
   - registration_start, registration_deadline
   - competition_start, competition_end
   - results_announcement_date
   - status (draft, published, ongoing, judging, completed, cancelled)
   - is_active
   - created_by (FK → users, nullable)
   - created_at, updated_at, deleted_at

================================================================================
JUNCTION/RELATIONSHIP TABLES
================================================================================

9. teacher_clubs
   - id (PK)
   - user_id (FK → users)
   - club_id (FK → clubs)
   - school_id (FK → schools, nullable)
   - created_at, updated_at
   - UNIQUE(user_id, club_id)

10. students
    - id (PK)
    - teacher_club_id (FK → teacher_clubs)
    - name
    - age
    - gender (male, female, other)
    - school_class_id (FK → school_classes)
    - created_at, updated_at

11. model_questions
    - id (PK)
    - model_id (FK → model3ds)
    - question_type (mcq, true_false, short_answer)
    - question_text
    - options (JSON)
    - correct_answer
    - explanation
    - order
    - created_at, updated_at

12. vr_question_banks
    - id (PK)
    - vr_experiment_id (FK → vr_experiments)
    - title
    - description
    - time_limit (minutes)
    - passing_score (percentage)
    - is_active
    - display_order
    - created_at, updated_at

13. vr_questions
    - id (PK)
    - question_bank_id (FK → vr_question_banks)
    - question_type (mcq, true_false, short_answer)
    - question_text
    - options (JSON)
    - correct_answer
    - explanation
    - points
    - order
    - created_at, updated_at

14. competition_awards
    - id (PK)
    - competition_id (FK → competitions)
    - position (1st, 2nd, 3rd, etc.)
    - title
    - description
    - prize_type
    - prize_value
    - prize_image
    - created_at, updated_at
    - UNIQUE(competition_id, position)

15. competition_participants
    - id (PK)
    - competition_id (FK → competitions)
    - teacher_club_id (FK → teacher_clubs)
    - team_name
    - team_description
    - status (pending, approved, rejected, withdrawn, disqualified)
    - rejection_reason
    - award_id (FK → competition_awards, nullable)
    - final_score
    - rank
    - registered_at
    - approved_at
    - created_at, updated_at
    - UNIQUE(competition_id, teacher_club_id)

16. competition_participant_students
    - id (PK)
    - competition_participant_id (FK → competition_participants)
    - student_id (FK → students)
    - role (Team Leader, Researcher, Presenter, etc.)
    - created_at, updated_at
    - UNIQUE(competition_participant_id, student_id)

17. competition_submissions
    - id (PK)
    - competition_participant_id (FK → competition_participants)
    - title
    - description
    - methodology
    - results
    - conclusion
    - materials_used
    - challenges_faced
    - learning_outcomes
    - status (draft, submitted, under_review, reviewed, revision_requested)
    - submitted_at
    - score
    - judge_feedback
    - judged_by (FK → users, nullable)
    - judged_at
    - version
    - created_at, updated_at

================================================================================
TRANSACTION/ACTIVITY TABLES
================================================================================

18. model_question_answers
    - id (PK)
    - user_id (FK → users)
    - model_id (FK → model3ds)
    - question_id (FK → model_questions)
    - student_answer
    - is_correct
    - score
    - created_at, updated_at

19. vr_assessment_attempts
    - id (PK)
    - user_id (FK → users)
    - question_bank_id (FK → vr_question_banks)
    - started_at
    - completed_at
    - score (percentage)
    - correct_answers
    - total_questions
    - passed
    - created_at, updated_at

20. vr_question_answers
    - id (PK)
    - attempt_id (FK → vr_assessment_attempts)
    - question_id (FK → vr_questions)
    - student_answer
    - is_correct
    - points_earned
    - created_at, updated_at
    - UNIQUE(attempt_id, question_id)

21. submission_attachments
    - id (PK)
    - competition_submission_id (FK → competition_submissions)
    - type (pdf, image, document, video, other)
    - file_path
    - original_filename
    - mime_type
    - file_size (bytes)
    - caption
    - description
    - order
    - category
    - created_at, updated_at

================================================================================
RELATIONSHIPS SUMMARY
================================================================================

users
  ├──→ teacher_clubs (1:N)
  ├──→ model_question_answers (1:N)
  ├──→ vr_assessment_attempts (1:N)
  ├──→ competitions (created_by, 1:N)
  └──→ competition_submissions (judged_by, 1:N)

subjects
  ├──→ model3ds (1:N)
  └──→ vr_experiments (1:N, nullable)

school_classes
  ├──→ students (1:N)
  └──→ vr_experiments (1:N)

schools
  └──→ teacher_clubs (1:N, nullable)

clubs
  ├──→ teacher_clubs (1:N)
  └──→ competitions (1:N)

teacher_clubs
  ├──→ students (1:N)
  └──→ competition_participants (1:N)

model3ds
  ├──→ model_questions (1:N)
  └──→ model_question_answers (1:N)

model_questions
  └──→ model_question_answers (1:N)

vr_experiments
  └──→ vr_question_banks (1:N)

vr_question_banks
  ├──→ vr_questions (1:N)
  └──→ vr_assessment_attempts (1:N)

vr_questions
  └──→ vr_question_answers (1:N)

vr_assessment_attempts
  └──→ vr_question_answers (1:N)

competitions
  ├──→ competition_awards (1:N)
  ├──→ competition_participants (1:N)
  └──→ users (created_by, N:1)

competition_awards
  └──→ competition_participants (1:N, nullable)

competition_participants
  ├──→ competition_participant_students (1:N)
  └──→ competition_submissions (1:N)

students
  └──→ competition_participant_students (1:N)

competition_submissions
  ├──→ submission_attachments (1:N)
  └──→ users (judged_by, N:1, nullable)

================================================================================
KEY CONSTRAINTS
================================================================================

UNIQUE CONSTRAINTS:
- users.email
- school_classes.name
- schools.name
- clubs.name
- competitions.slug
- teacher_clubs(user_id, club_id)
- competition_awards(competition_id, position)
- competition_participants(competition_id, teacher_club_id)
- competition_participant_students(competition_participant_id, student_id)
- vr_question_answers(attempt_id, question_id)

FOREIGN KEY CONSTRAINTS:
- All FK relationships maintain referential integrity
- CASCADE deletes where appropriate
- SET NULL for optional relationships (created_by, judged_by, award_id)

INDEXES:
- Performance indexes on frequently queried columns
- Composite indexes on common query patterns
- Indexes on foreign keys for join performance
